# Следующий этап: звук, аудирование и видео

Статус на 30.10.2026: первый этап аудирования реализован. Опубликованы 10 занятий A1–C1 (четыре записи VOA и шесть учебных записей), цикл «смысл → детали → слово → разбор», повтор A–B, скорости, сохранение позиции, отдельные показатели понимания и написания, учёт текстовой поддержки, история и XP. Старые короткие режимы сохранены. Видеофрагменты ещё не подключены. Далее — больше записей живой речи, таймкоды реплик и разрешённые видео с субтитрами. Ниже — исходный план развития.

## 1. Разделить две задачи

**Звуки интерфейса** помогают заметить результат ответа. Они короткие, негромкие, отключаемые и не должны звучать одновременно с речью. Они не тренируют понимание английской речи. Уже реализован базовый вариант через Web Audio API, выключенный по умолчанию.

**Аудирование** учит понимать речь. Синтез устройства полезен для слов и коротких диктантов, но следующая библиотека должна включать реальные записи с естественными паузами, связной речью и разными говорящими.

## 2. Один понятный сценарий занятия

Предлагаемый сценарий — 5–10 минут:

1. Короткая вводная: ситуация и задача, без раскрытия ключевого ответа.
2. Первое прослушивание: без текста; один вопрос на основную мысль.
3. Второе: два-три вопроса о деталях.
4. Работа с коротким фрагментом: пропущенное слово, различение похожих слов или диктант.
5. Проверка с расшифровкой и выделением места, где находится ответ.
6. Повторное прослушивание и, по желанию, проговаривание вслед за диктором.
7. Итог: что удалось понять самостоятельно, какие слова добавить в повторение.

Не смешивать «понял содержание» с «точно написал текст»: это отдельные показатели. Сохранить, был ли открыт текст до ответа, число повторов и выбранную скорость. Задания с открытой расшифровкой учитывать как тренировку с поддержкой, без заявления о независимом понимании речи.

## 3. Небольшая первая библиотека

Начать с 12–18 качественно проверенных фрагментов для A1–B2. Для A0 — знакомые слова и простые инструкции; C1–C2 добавить после проверки сценария на более коротких материалах.

- A1: 15–30 секунд, один говорящий, ясная бытовая ситуация.
- A2: 30–45 секунд, короткие диалоги и последовательность действий.
- B1: 45–75 секунд, основная мысль, детали, связная речь.
- B2: 60–120 секунд, несколько говорящих, отношение и вывод из контекста.

Это ориентиры для подбора, а не автоматическая сертификация уровня. Каждому фрагменту нужны проверенные задания и расшифровка.

## 4. Видео как контекст, а не как фон

Первый формат: законченный фрагмент на 20–60 секунд — знакомство, заказ, просьба, уточнение, короткое объяснение. Два режима: «слушаю с изображением» и «слушаю без изображения», если исходный материал и условия использования позволяют.

Плеер: воспроизведение/пауза, громкость, перемотка, скорости 0,75× / 1× / 1,25×, повтор выбранной реплики, субтитры и отдельная расшифровка. Субтитры в учебном первом проходе скрыты, но всегда доступны по выбору пользователя; предпочтения доступности важнее сценария. Никакого фонового автовоспроизведения.

Не подменять встроенный плеер YouTube/Vimeo собственным и не вырезать/скачивать чужие ролики без соответствующих разрешений. При внешнем встраивании учитывать доступность сервиса и требования к персональным данным. Альтернатива — собственные записи или явно разрешённые материалы с локальными MP4/WebM и WebVTT.

## 5. Содержимое карточки фрагмента

```json
{
  "id": "a2-cafe-01",
  "level": "A2",
  "kind": "video",
  "title": "Уточнить заказ",
  "durationSeconds": 38,
  "speakers": 2,
  "accent": "описание после проверки",
  "src": "media/проверенный-файл.mp4",
  "captions": "captions/проверенный-файл.en.vtt",
  "transcript": [{"start": 0.0, "end": 3.2, "text": "Проверенная реплика"}],
  "source": {"url": "адрес первоисточника", "author": "автор", "license": "условия использования"},
  "tasks": {"gist": [], "details": [], "dictation": []}
}
```

Это схема, а не опубликованный ролик. Перед добавлением проверяются права, соответствие уровня, смысл вопросов и таймкоды.

## 6. Техническая реализация на текущем GitHub Pages

- Небольшой каталог JSON и ленивое подключение медиа. Для `<video>` / `<audio>` — `preload="metadata"`, стандартные доступные элементы управления на первом этапе.
- Воспроизведение только после действия пользователя. Браузеры могут блокировать аудио и видео с активной звуковой дорожкой, запускаемые автоматически: [MDN, Autoplay guide](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay).
- Субтитры через `<track>` и WebVTT; подробности: [MDN, Audio and video delivery](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Audio_and_video_delivery), [MDN, video](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/video).
- Состояние занятия: `clipId`, ответы, `transcriptOpenedAt`, количество повторов, скорость, текущая реплика, прогресс. Всё сохраняется локально и входит в резервную копию.
- При переходе между разделами останавливать запись; не допускать одновременного звучания речи, клипа и сигнала ответа.
- Для большой медиатеки вынести файлы в подходящее хранилище с поддержкой Range-запросов и CORS; GitHub Pages оставить интерфейсом. Выбор хранилища сделать после оценки объёма.

## 7. Материалы и проверка качества

Предпочтение — собственные диалоги с разрешением дикторов либо материалы с подходящей лицензией. Публичный доступ к учебному видео не равен разрешению копировать его: например, [British Council Terms](https://www.britishcouncil.org/terms) отдельно описывают права на аудио, видео и другие учебные материалы. Внешние учебные сайты можно давать как ссылки, не обещая право на встраивание или переработку.

Перед выпуском: телефон и компьютер; клавиатура и экранный диктор; работа субтитров; восстановление после паузы; плохое соединение; недоступный голос; отсутствие автозвука; отсутствие наложений. Проверить вопросы на неоднозначность и раздельно показывать результаты понимания и диктанта.

## 8. Порядок внедрения

1. Мини-библиотека реального аудио и общий плеер.
2. Цикл из трёх прослушиваний с расшифровкой и повторением реплик.
3. Небольшой набор разрешённых видеофрагментов с таймкодами и субтитрами.
4. Повторение слабых фрагментов и отдельная статистика аудирования.
5. Расширение уровней и голосов по результатам использования.
