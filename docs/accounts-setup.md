# Аккаунты на GitHub Pages

Сайт остаётся статическим; Supabase предоставляет Auth и Postgres через HTTPS. Клиент использует официальный REST API Auth и PostgREST без сторонних CDN-скриптов.

## Настройка

1. Создать проект Supabase, включить вход Email. Подтверждение почты оставить включённым.
2. Authentication → URL Configuration: Site URL и разрешённый Redirect URL — `https://citer529212.github.io/ekvivalent/`.
3. Выполнить `supabase/accounts.sql` в SQL Editor. Скрипт создаёт таблицу прогресса и функцию атомарного сохранения. RLS разрешает чтение/изменение только строки с `user_id = auth.uid()`. У роли anon нет прав к таблице и функции.
4. Указать Project URL и публичный publishable key в `account-config.js`. Секреты в клиент не добавлять.
5. Опубликовать файлы и зарегистрировать собственный аккаунт, подтвердить письмо, пройти несколько заданий и проверить вход с другого телефона.

## Письма

Доставку подтверждения и восстановления выполняет Supabase. Перед приглашением всей группы подключить собственный SMTP-провайдер в Authentication → Email, проверить доставку и действующие лимиты проекта. Встроенный почтовый сервис имеет ограничения и предназначен для пробного использования; успешный запрос сам по себе не подтверждает доставку письма ученику.

## Хранение и конфликты

`english-compass-v1` остаётся гостевым хранилищем. Аккаунты используют отдельные ключи по UUID. Серверный прогресс хранится в `ekvivalent_progress`, пароли — в Supabase Auth. Сессия хранится локально и обновляется refresh-токеном; пароль в localStorage и JSON-экспорт не включается.

Сохранение сравнивает ожидаемую ревизию строки с текущей. Устаревшее устройство получает конфликт вместо перезаписи. Пользователь может скачать локальную копию и выбрать нужную версию. До первого успешного чтения сервера отправка блокируется; ошибка сети не делает пустой локальный профиль основной облачной версией.

Выход возвращает гостевой профиль. Локальная копия аккаунта остаётся для восстановления неотправленных изменений, но не открывается интерфейсом гостя. Очистка данных браузера удаляет эту копию и сессию. Сброс учебного прогресса синхронизируется при входе; удаление самой учётной записи выполняет владелец в Supabase Authentication.
